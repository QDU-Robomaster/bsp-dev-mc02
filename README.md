# bsp-dev-mc02

MC02 开发板（STM32H723VGTx）的 LibXR / XRobot BSP / LibXR and XRobot BSP for the MC02 board (STM32H723VGTx)

## 1. 板子与平台 / Board and Platform

MC02 开发板使用 STM32H723VGTx，系统为 FreeRTOS，终端通过 USB HS CDC（`usb_otg_hs_cdc`）提供。外设由 CubeMX 工程 `CtrBoard-H7_ALL.ioc` 配置，`libxr` 命令生成入口源文件 `User/app_main.cpp`，并在其中用 `XR_REGISTER` 完成硬件注册，覆盖 GPIO、PWM、ADC、DAC、SPI、UART、FDCAN、RamFS、终端和 Database。每个 FDCAN 同时以 `fdcanN`（`LibXR::FDCAN`）和 `canN`（`LibXR::CAN`）注册。配置中的硬件名即这些注册名，例如 `pwm_tim12_ch2`、`spi2`、`usart1`、`fdcan1`。

```text
CtrBoard-H7_ALL.ioc       CubeMX 工程
Core/ Drivers/            CubeMX 生成的初始化代码与 ST HAL / CMSIS
Middlewares/              FreeRTOS、LibXR 子模块
Modules/modules.yaml      使用的模块（`xrobot:` 记录 XRobot 版本）
Modules/sources.yaml      源
xrobot.lock               每个模块使用的提交（lock）
User/app_main.cpp         入口源文件，硬件注册并调用 XROBOT_MAIN()
User/libxr_config.yaml    LibXR 外设参数（`generator:` 记录 CodeGenerator 版本）
User/xrobot.yaml          配置
```

`Modules/<owner>/<Repo>/`、`Modules/CMakeLists.txt` 和 `User/xrobot_main.hpp` 由 `xrobot` 生成，已列入 `.gitignore`。

The MC02 board uses an STM32H723VGTx and runs FreeRTOS. The terminal is provided over USB HS CDC (`usb_otg_hs_cdc`). The peripherals are configured in the CubeMX project `CtrBoard-H7_ALL.ioc`; the `libxr` command generates the entry source `User/app_main.cpp`, which performs the hardware registration with `XR_REGISTER` for GPIO, PWM, ADC, DAC, SPI, UART, FDCAN, RamFS, the terminal and the Database. Each FDCAN is registered both as `fdcanN` (`LibXR::FDCAN`) and as `canN` (`LibXR::CAN`). The hardware names used in a configuration are these registered names, for example `pwm_tim12_ch2`, `spi2`, `usart1` and `fdcan1`.

`Modules/<owner>/<Repo>/`, `Modules/CMakeLists.txt` and `User/xrobot_main.hpp` are generated by `xrobot` and listed in `.gitignore`.

## 3. 构建 / Build

构建使用 CMake、Ninja 和 ST 的 `starm-clang` 工具链（STM32CubeCLT 或 VS Code STM32Cube 扩展提供），`starm-clang` 位于 `PATH` 中。预设使用 `cmake/starm-clang.cmake`（picolibc 配置）。XRobot 为 1.0.0，LibXR CodeGenerator 为 6.0.0，与 `Modules/modules.yaml` 的 `xrobot:` 和 `User/libxr_config.yaml` 的 `generator:` 一致。

```bash
git clone --recursive https://github.com/QDU-Robomaster/bsp-dev-mc02.git
cd bsp-dev-mc02
pip install xrobot==1.0.0 libxr==6.0.0
xrobot setup
cmake --preset Debug
cmake --build --preset Debug
```

`xrobot setup` 拉取模块、检查配置并生成 `User/xrobot_main.hpp`。CMake 预设为 `Debug` 和 `Release`，产物为 `build/<预设>/CtrBoard-H7_ALL.elf`。构建时 LibXR 检查配置、lock、模块头文件和入口源文件中的硬件注册相对 `User/xrobot_main.hpp` 是否有变化，有变化时构建失败并提示对应的 `xrobot gen -c <配置>`。

在 CubeMX 中修改并重新生成代码后，运行 `libxr stm32 setup` 更新 `User/app_main.cpp`、`User/app_main.h`、`User/flash_map.hpp`、`User/libxr_config.yaml` 和 `cmake/LibXR.CMake`，`User Code` 区域保留。命令说明见 [LibXR_CppCodeGenerator](https://github.com/xrobot-org/LibXR_CppCodeGenerator)。

`.github/workflows/xrobot_stm32.yml` 在 `ghcr.io/xrobot-org/docker-image-stm32:main` 中安装固定版本的工具，用 `libxr parse` 和 `libxr gen` 重新生成上述文件并与提交比对，运行 `xrobot format --check` 和 `xrobot setup --frozen`，再构建固件。`dev` 分支接收修改，`master` 分支由 `dev` 的 PR 更新。

Building uses CMake, Ninja and ST's `starm-clang` toolchain (provided by STM32CubeCLT or the VS Code STM32Cube extension), with `starm-clang` on `PATH`. The presets use `cmake/starm-clang.cmake` (picolibc configuration). XRobot is 1.0.0 and the LibXR CodeGenerator is 6.0.0, matching `xrobot:` in `Modules/modules.yaml` and `generator:` in `User/libxr_config.yaml`.

`xrobot setup` fetches the Modules, checks the configurations and generates `User/xrobot_main.hpp`. The CMake presets are `Debug` and `Release`, and the output is `build/<preset>/CtrBoard-H7_ALL.elf`. During the build, LibXR checks whether the configurations, the lock, the Module headers and the hardware registrations in the entry source changed relative to `User/xrobot_main.hpp`; on a change the build fails and names the matching `xrobot gen -c <configuration>`.

After changing and regenerating the code in CubeMX, `libxr stm32 setup` updates `User/app_main.cpp`, `User/app_main.h`, `User/flash_map.hpp`, `User/libxr_config.yaml` and `cmake/LibXR.CMake`, and keeps the `User Code` regions. The commands are described in [LibXR_CppCodeGenerator](https://github.com/xrobot-org/LibXR_CppCodeGenerator).

`.github/workflows/xrobot_stm32.yml` installs the pinned tools in `ghcr.io/xrobot-org/docker-image-stm32:main`, regenerates the files above with `libxr parse` and `libxr gen` and compares them with the commit, runs `xrobot format --check` and `xrobot setup --frozen`, and then builds the firmware. The `dev` branch receives changes and the `master` branch is updated by PRs from `dev`.

## 4. 烧录与运行 / Flash and Run

`DevMC02.jdebug` 是 SEGGER Ozone 工程，设备为 STM32H723VG，调试接口为 SWD（4 MHz），加载 `build/Debug/CtrBoard-H7_ALL.elf`。先构建 `Debug` 预设，再在 Ozone 中打开该工程即可下载并调试。运行后通过 USB HS CDC 连接终端。

`DevMC02.jdebug` is a SEGGER Ozone project for the STM32H723VG over SWD (4 MHz) that loads `build/Debug/CtrBoard-H7_ALL.elf`. After building the `Debug` preset, opening the project in Ozone downloads and debugs the firmware. At run time the terminal is available over USB HS CDC.
